# Cloud reel autopilot

An unattended production job and a paused-by-default Cloudflare scheduler for the 60-lesson course. The configured cadence is **daily at 11:00 AM Asia/Kolkata**, with generation six hours earlier. The first date is assigned only after a successful cloud pilot.

## Components

- `catalog.py`: exports the approved curriculum and creates time-zone-aware release dates.
- `content.py`: accepts bounded scene JSON from Gemini, or a reviewed pilot lesson. No generated code is executed.
- `voice.py`: voice-provider dispatcher; Kokoro remains available for explicitly configured local use.
- `gemini_voice.py`: Gemini Varo continuous scene narration and local Whisper alignment for verbatim captions.
- `render.py`: trusted HTML/GSAP diagram families and local fonts.
- `thumbnail.py` and `thumbnails/`: branded 1080×1920 covers rendered with the channel's existing `ReelThumbnail` component. Each cover shows the module name, video number within that module, and overall lesson number. Text is checked against the central crop area before rendering completes.
- `produce.py`: content → voice → composition → browser checks → MP4 → validation → optional upload/callback. It never publishes to Instagram.
- `cloudflare/src/worker.mjs`: claims jobs, prepares Instagram media, publishes due releases and reconciles uncertain results.
- `setup.py`: credential checks, encrypted GitHub secrets, paused cloud deployment, cloud pilots, queue activation and pause.
- `.github/workflows/reel-production.yml`: reusable Linux production workflow.
- `.github/workflows/reel-pilot.yml`: on the implementation branch, renders two pilots without uploading or publishing.

The existing local Mac publisher remains untouched. It must not own the same dated queue as the cloud worker when live operation begins.

## Verified protections

The producer contains no Instagram publishing credentials. The scheduler uses persisted state and atomic claims. A publish timeout enters `PUBLISH_UNKNOWN`; it checks the stored container instead of issuing another publish request. Old job callbacks cannot replace a current result. Authentication and owned Cloudinary origins are checked. Invalid audio/video evidence is rejected. A missed window holds the lesson and preserves curriculum order.

The public `/health` endpoint reports only the service name. Detailed status and queue controls require an administrator token. Production callbacks use a different token. New deployments start with generation and publication paused in D1.

From the repository root:

```sh

npm ci
.autopilot/venv/bin/python -m automation.setup doctor
```

Generated projects, reports, audio, model files and videos go into ignored `.autopilot/`. `--upload` is a separate explicit option. It uploads to the configured Cloudinary account; it still does not publish.

## Course thumbnails

Each scheduled production job generates its own dedicated cover on demand, instead of extracting the third second of the video. No batch of future cover images is required or generated by the schedule. The job saves `cover.png` for review and `cover.jpg` for Instagram, with metadata in `cover.json`. The scheduler already supplies the returned cover URL when it creates the Reel container. Cover styling has a separate hash so changing a cover does not invalidate the video's narration or frame cache. This does not change dates, course order, voice, or publishing settings.

To render covers without generating speech, videos, uploads or posts:

```sh
python3 -m automation.thumbnail --lesson lesson-01       # One cover
```

The header identifies the module and `VIDEO n OF total`; the module title appears above the lesson headline. Module counts come from the actual curriculum, so numbering resets at every module boundary. `automation/thumbnails/covers.json` contains concise, reviewed cover copy; no image model or external fonts are required. Existing thumbnail compositions keep their default appearance.

Two hand-authored pilot lesson packets are included: requirements (`lesson-01`) and atomic inventory claims (`lesson-28`). Remaining lessons use Gemini content generation. Pilot availability does not mean all 60 finished scripts have been authored or fact checked. The catalog contains each lesson's scope, caveat and sources. AI-generated content requires the specified schema/technical gates; those are not proof of factual accuracy.

## Course voice

The production voice is local Kokoro **Fenrir** (`am_fenrir`, Kokoro v1.0 ONNX), running on the GitHub CPU runner at speed1.0. Voice synthesis needs no API key and makes no hosted voice-provider request. The first run downloads the model and voice files; subsequent runs reuse the existing model cache. The full script becomes one waveform, normalized with FFmpeg. Local Whisper measures word times and builds short verbatim captions using the same agreement and scene-boundary checks as the Gemini path. Invalid, silent or badly aligned speech stops the job. Gemini Varo remains an explicit supported alternative, but there is no automatic paid/provider fallback.

Voice/model/style identity participates in narration and media hashes, so a resumed Kokoro job cannot reuse its old voice audio as Varo. Gemini rate limits and temporary service errors receive bounded retries; permanent access errors stop. There is no automatic change of voice or paid provider. The scheduler's existing retry/hold policy applies if narration fails.

Speech responses and alignment data are cached per script and voice profile. The workflow restores the script and completed scenes from the most recent compatible attempt and saves progress even when production fails; retries use `--resume`. Cached progress excludes credentials, job tokens, and callback results. The small Whisper model is cached on the GitHub runner. Source deployment defaults remain paused; live dates and enabled state are held in Cloudflare D1 and are not changed by a voice update.

### Interrupted script recovery

With `--resume`, the producer saves the prompt identity, frozen Insights, draft and local validation result before requesting a correction. GitHub caches `script-progress.json` and `script-attempts.json` even when production fails. A retry resumes the saved draft's correction rather than requesting another initial draft. A validated checkpoint is revalidated and reused if the final content file was not written before interruption. Lesson, model, prompt, schema, policy or frozen-feedback changes invalidate incompatible checkpoints.

The initial draft plus one completed correction is the total validation budget across runs; an invalid second response stops without further model calls. A failed HTTP request leaves the same pending correction available for retry. Script requests use at most three HTTP attempts per logical request to leave time within the hosted job limit. Narration remains one continuous, cached Varo performance.

A provider's daily quota reset or long cooldown is saved in the script checkpoint. A resumed job before `retry_at` defers without contacting Gemini; it can continue after that time. This records when a retry is permitted, not a guarantee of provider capacity. Existing publication windows and ordered-release safeguards still apply; this change does not move dates, publish late or switch providers.

### Gemini quota handling

Google measures limits per project and model across requests per minute, input tokens per minute, and requests per day. The actual account limits are shown in [AI Studio](https://aistudio.google.com/usage?timeRange=last-28-days&tab=rate-limit); they are not universal guarantees. Daily request quotas reset at midnight in `America/Los_Angeles`, including daylight-saving changes. See [Google's rate-limit guide](https://ai.google.dev/gemini-api/docs/rate-limits).

Production starts voice requests at least **65 seconds apart** (`gemini_voice_interval_seconds`), a conservative one-request-per-minute policy rather than an assumed account entitlement. All production workflows share one concurrency group to avoid overlapping narration jobs. Other clients using the same Google project still share its quota.

Both content and voice REST calls use bounded exponential backoff with jitter for transient network errors and HTTP 408, 429, 500, 502, 503 and 504, honoring `Retry-After` and structured `google.rpc.RetryInfo` hints. Daily quota errors stop the job and defer the scheduler until the next Pacific reset (or a later provider hint); long cooldowns also defer rather than occupy a runner. A cooldown beyond publication's existing deadline holds the lesson and preserves order. Errors such as 400/402/403 stop immediately. No billing, model, or voice switch is performed. See [Google's retry guidance](https://ai.google.dev/gemini-api/docs/troubleshooting#retry-strategy).

Allowlisted diagnostics record HTTP status, quota category, and retry time in `generation-error.json` and the job log. Raw API errors and credential-bearing URLs are never logged. An unclassified 429 gets bounded backoff; spacing cannot bypass a daily quota or guarantee that a shared project will never be throttled.

## Account setup

Existing Meta/Instagram and Cloudinary values can stay in ignored `.env`. Run:

```sh
.autopilot/venv/bin/python -m automation.setup credentials
```

The command prompts in the local terminal, with hidden input, for:

- Cloudflare account ID and an account-scoped token with Workers Scripts Edit and D1 Edit.
- A Google AI Studio free-tier API key.
- GitHub access if the repository's Git credential helper is not already configured.

It generates separate administrator/callback tokens and saves them to ignored `.env.autopilot` with owner-only permissions. Never send credential values in chat. `automation/.env.example` lists the variables.

The deployment command transfers the configured credentials to the expected providers: Cloudinary/Gemini/callback credentials become encrypted secrets in this repository's GitHub Actions; Instagram and dispatch credentials become Cloudflare Worker secrets. Obtain authorization for these transfers before running deployment. A GitHub secret called `AUTOPILOT_CLOUDINARY_URL` keeps this pipeline separate from existing integrations.

Do not use paid Gemini billing as an automatic fallback. If the free-tier call fails, the scheduler retries at most three production attempts and then holds the lesson. There is no automatic charge-bearing provider switch.

## Cloud deployment and activation

Merge the reviewed implementation branch so `.github/workflows/reel-production.yml` exists on the repository's default branch. Then:

```sh
.autopilot/venv/bin/python -m automation.setup deploy
.autopilot/venv/bin/python -m automation.setup pilot --lesson lesson-01
.autopilot/venv/bin/python -m automation.setup pilot --lesson lesson-28
.autopilot/venv/bin/python -m automation.setup status
```

Deployment creates/uses a D1 database, applies its migration, deploys a paused Worker and configures secrets. No dates or live publication are enabled. `wrangler.deployed.json` is generated locally and ignored. The source config contains a database placeholder and cannot deploy without setup.

The Worker must receive at least one successful uploaded GitHub dry-run callback before activation. Verify both pilot videos, actual Linux runtimes, and the Gemini provider before live operation. To verify generation once the key is available:

```sh
.autopilot/venv/bin/python -m automation.produce --lesson lesson-02 --provider gemini --prepare-only
```

Choose a first matching date with at least six hours remaining before the generation start. Use the user-approved date, not the example below:

```sh
.autopilot/venv/bin/python -m automation.setup activate --start-date YYYY-MM-DD
.autopilot/venv/bin/python -m automation.setup pause
```

Activation imports all 60 dated entries, verifies Instagram account access and enables the Worker. It is the live-publication switch. Do not run it before the pilot/review and account-transfer requirements are satisfied.

Inspect cloud jobs independently with:

```sh
.autopilot/venv/bin/python -m automation.setup runs
```

## Operating boundaries

- Publication is minute-oriented and subject to platform delays; it is not an exact-second guarantee.
- Expired tokens, API changes and quota exhaustion can require intervention.
- A held or ambiguous lesson is intentionally not automatically republished; inspect its container/post and reset its state deliberately after resolving the cause.
- On the free Worker plan, profile CPU use before live operation. Keep rendering and speech on the hosted Linux job.
- Models, dependencies and seven-day review artifacts consume cache/storage. Benchmark the full Linux workload before choosing the ongoing cadence.
- The implementation branch's automatic pilot uploads nothing. Uploaded pilots with callbacks are initiated explicitly after deployment.

## Daily creative policy and Insights

The approved default is a light workshop reel, a dark series cover with a truthful curiosity-led headline, and continuous English Gemini Varo narration. The v2 story and encoded opening gate below now supersede the earlier generic six-scene renderer. Every new script follows one concrete example, brings a useful contrast into the opening teaching beat, and ends with a reusable diagnostic or reference. Captions are measured 3–5-word groups. Technical ASR spellings are normalized for matching; a failed tiny.en alignment gets one local base.en check on the same audio, with the same strict agreement and boundary checks. `creative-policy.json` records the approved direction and the small-sample baseline. The renderer is pinned to HyperFrames 0.8.198, checked locally; hosted rehearsals verify the Linux production path.

Before a new Gemini script, the producer reads `/api/creative-feedback` from the configured Worker using its existing callback credential. The Worker fetches at most 20 recent videos. Version 2 labels 3–72-hour observations as provisional and separates observations aged 72 hours–30 days; younger and older posts are excluded. Only allowlisted numeric metrics and course lesson IDs return; captions and Instagram tokens stay in the Worker. Lifetime totals at unequal ages remain descriptive. An unavailable API preserves the approved style and records unavailability without inventing metrics. Feedback is saved once per lesson and frozen across retries; a policy/prompt change invalidates its cached script. No automatic theme switches, topic winner claims, paid fallbacks or course reordering.

For an already active queue, preview an update with `python -m automation.reschedule --start-date YYYY-MM-DD`, then apply with `--apply` only when authorized. This requires the full ordered 60-lesson queue, an unstarted remaining suffix and a future six-hour generation lead. One compare-guarded SQLite statement changes the remaining dates atomically. Published history and scheduler switches are verified afterward. Never re-import a running queue.

## Story correction v2 — 27 October 2026

Future Gemini scripts use eight short beats around one concrete example. A physical two-path contrast is visible at entry and its consequence lands at 2.4 seconds. Beat two advances the input instead of restating the problem. Supported mechanism actions have explicit endpoint counts and finite connected paths: routing, filtering, queuing, fanout, replication, lookup, cache hit/miss and retry. The close contains three actionable diagnostic checks. The light palette, dark series covers, daily 11 AM IST slot and English Varo voice remain unchanged.

Local validation rejects the former generic schema, repeated opening wording, long setup, missing/overlong diagnostics and unsupported action geometry. A script gets at most one correction before narration. After rendering, the gate decodes the actual 0/1.5/3-second frames and measures the two packet positions: both must exist at entry, one must stop at its boundary and the other must arrive by three seconds. The Worker rejects a result without story-v2 evidence and a passing review tied to the encoded file hash. This is constrained deterministic QA, not a claim of human-level semantic judgment or guaranteed reach. The deployment pilot also gets a visual review.

Rendered frames stay on the runner and in the existing GitHub review artifact. No new image-review API is used. `creative-review.json`, `story-evidence.json`, `STORYBOARD.md`, `SPEC.md`, `script-attempts.json` and `creative-frames/` make the creative evidence inspectable alongside technical checks.

Insights now have two separate channels: `early_reels` (3–72 hours, explicitly provisional) and `reels` (72 hours–30 days). Neither makes unequal-age totals comparable. Course topics are annotated from the trusted local catalog, not raw captions. The Worker records actual snapshot age/time. Its existing minute cron independently claims 24-hour, 72-hour and seven-day observations for published course reels, within 15 minutes of the target. Collection failures back off and never alter publishing state. Missed windows are not reconstructed from later lifetime values. `matched_age_observations` exposes only real recorded windows.

Deploy migration `0002_insight_observations.sql` before the Worker update. It adds observation tables without rewriting lessons, published history, dates, switches or credentials. Keep the producer and Worker story-gate versions together; the old approved pilot JSON remains a historical fixture and is not accepted by the v2 renderer.


## Script request latency — 29 October 2026

Gemini 3 Flash script calls explicitly use minimal thinking and the vendor-recommended temperature 1.0. The change is limited to the supported `gemini-3-flash-preview` and `gemini-3-flash` models. Other model IDs retain their prior configuration, and Varo narration is unchanged. See https://ai.google.dev/gemini-api/docs/generate-content/gemini-3 for latency controls.

A script request has a 240-second read timeout with two transport attempts instead of discarding a slow response at 120 seconds up to three times. Quota-aware backoff, saved correction budgets and credential-safe error handling remain in force. Diagnostics now distinguish read/connect timeouts from other connection failures without logging raw exception text. Neither this change nor a fresh API key guarantees provider availability or quota.

The existing production workflow accepts `prepare_only: true` for a script-only preflight. It exits before speech, rendering, upload and callback, and retains the draft and progress in the usual cache/artifact for inspection. Use it to verify a future lesson without creating another video or modifying its publishing state.

### Reviewed script fallback and stage diagnostics

`generation-error.json` now identifies `script`, `voice`, `render`, `validation`, or `upload` so script quota failures cannot be mistaken for voice rate limits. Script requests use bounded transport retries; daily quota deferral remains preserved.

A fallback is disabled unless `automation/config.json` explicitly maps a lesson ID to the SHA256 of its reviewed `automation/lessons/lesson-NN.approved.json` bytes under `reviewed_script_fallbacks`. A Gemini script request or validation failure may use only that exact lesson file, after schema and story validation. Missing/changed files fail closed. `script-fallback.json` records use; no fallback publishes directly, bypasses rendering checks, substitutes another lesson, or changes the schedule. Voice remains Varo. New fallback scripts still need editorial review before enabling their hashes.

The current reviewed buffer enables hash-pinned fallbacks only for lessons 10 and 11. Their companion review files list sources and caveats. This protects those script stages from provider/validation failure; it does not guarantee voice availability, rendering success, publication availability or later lessons. Today's lesson remains held for user review; merging these changes does not publish it.


### Fenrir verification and cache identity

Kokoro identity includes provider, voice, model contract, speed and alignment model, so a Varo file cannot be reused after the switch. Changing Fenrir speed or alignment also invalidates narration reuse. Raw normalized waveforms and measured alignment are cached by full script plus voice identity; matching retries do not resynthesize. The renderer still requires measured short captions, the 45–105 second duration budget, audio levels, layout checks and encoded opening verification.

To roll back, revert the voice-switch PR; this restores the previous Varo voice/style configuration. Gemini script generation still uses `GEMINI_API_KEY`; switching speech does not remove the script provider’s requirement.
